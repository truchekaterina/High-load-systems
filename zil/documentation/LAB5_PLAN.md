# LAB5 — Python, requests, Faker: тестовые данные перед k6 (проект `zil`)

Документ для **новичка**: что сделать, **зачем** каждое действие, какими **простыми** средствами, и **как защищать** лабораторную (словом и через **Postman**).

- **Порт API:** `8083` (как в LAB4 / `docker compose`).
- **Бэкенд:** Spring Boot, PostgreSQL, Flyway (схема в `V1`, раньше — демо-INSERT в `V2` — по ТЗ данные оттуда **убираем**, заливаем из Python).
- **Файл коллекции Postman (импорт):** `zil/documentation/postman_collection.json` (при отсутствии — ищите `postman_collection.json` в корне `zil`).

---

## 1. Смысл задания (одним абзацем)

Перед **нагрузочным тестом** (k6) база **не должна** быть пустой «как пришлось» и **не обязана** наполняться **жёстким SQL** при деплое. Нужен **скрипт на Python**, который **сам** создаёт много **осмысленно выглядящих** записей через **REST** (`requests`) и **генератор фейковых данных** (`Faker`).

**Параметры запуска** (`--count`, `--endpoint` и т.д.) — чтобы **без правки кода** задать «сколько записей» и «что именно заливаем: клиентов, машины или аренды».

**Дополнительно по ТЗ:**

1. **Убрать initdb-логику по данным** — у нас это **не** `spring.sql.init` в `application.properties`, а **миграция Flyway** с **INSERT** в `V2__seed_data.sql`. **Таблицы** (`V1__init_schema.sql`) **остаются**; **демо-вставки** из `V2` **удаляем**, иначе при старте снова появятся «зашитые» строки, и смысл Python-заливки теряется.
2. **Эндпоинт очистки** (у нас: `POST /dev/clear`) — чтобы **одной командой** обнулить данные **перед** сидом **с учётом внешних ключей** (порядок удаления важен).

**Итог в двух фразах:** (1) источник **объёма** тестовых данных — **Python**; (2) перед k6: **подняли** приложение и БД → **очистили** → **залили** нужное число объектов → **запустили** k6.

## 2. Словарь: термины простым языком

| Термин | Что это |
|--------|---------|
| **REST / REST API** | Служба отвечает по **HTTP**: адрес `http://localhost:8083/...`, методы `GET` (прочитать), `POST` (создать), `DELETE` (удалить) и т.д. |
| **Эндпоинт** | «Путь + метод». Например, `POST /clients` — **создать клиента**. В задании аргумент `--endpoint` — **режим** скрипта: у **нас** — `clients`, `cars` или `rents` (аналог *users* / *tasks* из примера ТЗ). |
| **JSON** | Текстовый формат тела запроса/ответа: поля в фигурных скобках, кавычки у имён. Postman и `requests` умеют его слать/принимать. |
| **requests** | Библиотека Python: `requests.get(url)`, `requests.post(url, json={...})` — **как Postman**, но из программы. |
| **Faker** | Библиотека, которая **придумывает** похожие на правдивые строки: имена, компании, цвета. Это **не** реальные люди — **тестовая выдумка**. У нас в `seed.py` задана локаль, например `ru_RU`, чтобы имена выглядели привычно. |
| **Аргументы командной строки** | Запуск: `python seed.py --count 500 --endpoint clients`. Разбор делает **`argparse`** (стандартная библиотека Python) — **не** нужно менять число в коде. |
| **Виртуальное окружение (`.venv`)** | Отдельная папка с установленным `pip`-пакетам (`requests`, `faker`), **не** смешивая их с остальными проектами на ПК. |
| **Внешний ключ (FK)** | В таблице `rents` поля `car_id` и `client_id` **ссылаются** на строки в `cars` и `clients`. Сначала должны **существовать** машина и клиент, **потом** — аренда. **Очистка** идёт **наоборот:** сначала **аренды** (дочерние), потом **машины и клиенты** (родительские), иначе СУБД выдаст ошибку нарушения связи. |
| **Flyway** | При старте приложения **по порядку** выполняет SQL из `db/migration`: `V1` — **структура**, `V2` — **если** там INSERT — **начальные строки**. LAB5: **V1** оставляем, **INSERT из V2** убираем. |
| **Транзакция** (в Java) | Набор операций в БД, который **либо целиком применяется, либо откатывается**. Метод очистки помечают `@Transactional`, чтобы удаления шли **согласованно**. |

## 3. Что уже сделано в репозитории (к чему привязываться)

| Файл / место | Назначение |
|--------------|------------|
| `zil/seed.py` | Скрипт: `--count` (по умолчанию 500), `--endpoint` (`clients` \| `cars` \| `rents`), `--base-url` (по умолчанию `http://localhost:8083`), `--no-clear` (не вызывать очистку). Перед заливкой: `POST /dev/clear` (если не `--no-clear`). |
| `zil/requirements.txt` | Строки `requests` и `faker` — чтобы преподаватель или вы сами восстановили зависимости: `pip install -r requirements.txt`. |
| `zil/src/.../DevController.java` | `POST /dev/clear` → ответ **204 No Content** при успехе. |
| `zil/src/.../DevDataService.java` | Порядок: `rents` → `cars` → `clients` через `deleteAll()` **в одной транзакции**. **Только для dev / учёбы** — на проде такой URL **не** открывают. |
| `zil/src/main/resources/db/migration/V2__seed_data.sql` | Пока может содержать **INSERT** — по ТЗ LAB5 **нужно убрать** демо-данные (см. раздел 7). |
| k6 (LAB4) | После `seed` запускайте, например: `k6 run -e CREATE_SHARE=0.5 load.js` из папки `zil/k6`. |

**JSON-поля для API** (сверяйтесь с ответом `GET` и с телом в Postman):

- **Клиент:** `fullName`, `driverLicense`, `phone`.
- **Машина:** `vin`, `model`, `color`, `rentalCostPerDay` (**число** в JSON), `city`, `salonName`.
- **Аренда:** `carId`, `clientId`, `startDate`, `endDate` (ISO `YYYY-MM-DD`), `totalCost` (**число**).

**Режим `rents` в `seed.py`:** сначала создаётся `count` **клиентов** и `count` **машин** (id сохраняются в списки), затем `count` **аренд** со случайным выбором id и **валидными** датами (`end` позже `start`). Так закрывается требование «**зависимые таблицы** + сценарий `endpoint=rents`».

## 4. Пошаговая реализация (как в учебнике, без усложнений)

### Шаг A. Python: один раз на компьютере

1. Откройте терминал в папке **`zil`**: `cd C:\Users\1\Desktop\neurohelp\first_laba\zil` (путь уточните под свой).
2. Создайте окружение: `python -m venv .venv`
3. Установите пакеты (из активированного venv **или** явным путём к `python` — см. ниже):  
   `pip install -r requirements.txt`  
   или: `pip install requests faker`

**Важно для Windows + PowerShell:** активация через `.\.venv\Scripts\activate.bat` **иногда** оставляет команду `python` «не из venv», и появляется `ModuleNotFoundError: No module named 'faker'`. **Надёжно** вызывать:

```text
.\.venv\Scripts\python.exe seed.py --count 20 --endpoint clients
```

Так **гарантированно** используется Python из `.venv` с установленными пакетами.

### Шаг B. Поднять приложение и БД

Из папки `zil` (при установленном Docker):

```text
docker compose up --build -d
```

Проверка: в браузере или Postman `GET http://localhost:8083/cars` (ожидается **200** и JSON-массив; после очистки — пустой `[]`).

### Шаг C. Проверить очистку (Postman **или** `curl.exe`)

- **Postman:** метод **POST**, URL `http://localhost:8083/dev/clear`, **без** тела. Ожидаемый статус: **204 No Content** (в Postman внизу видно **Status**).
- **PowerShell:** не используйте одну букву `curl` как в Linux — это псевдоним. Явно:  
  `curl.exe -i -X POST http://localhost:8083/dev/clear`  
  В ответе должна быть строка `HTTP/1.1 204`.

### Шаг D. Залить данные

Примеры:

```text
.\.venv\Scripts\python.exe seed.py --count 500 --endpoint clients
.\.venv\Scripts\python.exe seed.py --count 100 --endpoint cars
.\.venv\Scripts\python.exe seed.py --count 50 --endpoint rents
```

**Порядок в жизни:** сначала **стенд поднят** (БД + app), потом **при необходимости** `POST /dev/clear` (скрипт делает сам), потом **seed**, потом **k6**.

**Если** нужно **дозалить** данные без полного сброса: `.\.venv\Scripts\python.exe seed.py --no-clear --count 10 --endpoint clients`.

### Шаг E. Нагрузка (как в LAB4)

После сида, из `zil/k6` (каталог с `load.js`):

```text
k6 run -e CREATE_SHARE=0.5 load.js
```

(Точные переменные — как в вашем `load.js`.)

## 5. Почему «обнуление + зависимые сущности» — не каприз, а смысл ТЗ

- **«Обнуление»** — вы **не** смешиваете старые демо-строки из Flyway с новой тысячей клиентов; каждый прогон k6 начинается **с чистого листа** (если не `--no-clear`).
- **«Генерация для зависимых»** — для `rents` **нельзя** просто `POST /rents` с выдуманными UUID: таких машин/клиентов в БД **нет**. Скрипт **сначала** создаёт **родителей** (клиентов, машины), **запоминает** их `id` из **ответа** API, **потом** строит аренды.

## 6. Как **убрать** демо-данные из Flyway, **сохранив** схему

1. Откройте `zil/src/main/resources/db/migration/V2__seed_data.sql`.
2. **Удалите** все `INSERT` (или замените файл на **пустой** с комментарием, что сид теперь через Python; главное — **не** выполнять вставки при миграции).
3. **Не трогайте** `V1__init_schema.sql` — таблицы **нужны**.

**Важно:** Flyway **запоминает**, какие миграции уже применялись. Если V2 **уже** накатили на старую базу, одно только редактирование файла **не** перезапишет прошлое. Для **чистой** проверки: новый **volume** PostgreSQL (например `docker compose down -v` — **сотрёт** данные БД; **осторожно** на важных данных) или новая тестовая БД. На защите честно скажите: «**Схема** из V1, **данные** — из Python; демо-INSERT из V2 убрали».

В `application.properties` **не** требуется отключать `spring.sql.init` **если** у вас **нет** `data-locations` — истинный «лишний» сид у нас в **V2**, не в Spring init.

## 7. Как **защищать** LAB5 (сценарий на 5–10 минут)

### 7.1. Что сказать в начале (тезисы)

1. **Задача:** перед k6 **массово** и **воспроизводимо** наполнить БД **через API**, с **похожими на реальные** полями (**Faker**), без **жёсткого** SQL-сида при деплое.
2. **Инструменты:** Python + **requests** (HTTP) + **Faker**; **argparse** для **CLI**; на бэке — **один** эндпоинт **очистки** с **правильным** порядком `delete` по **FK**.
3. **Почему `/dev/clear`:** чтобы **сценарий** «очистка → заливка N записей → нагрузка» был **одинаковый** на любом ПК, без ручного `DELETE` в SQL.

### 7.2. Демонстрация экрана (логичный порядок)

1. **Показать** `docker compose ps` (или в Docker Desktop) — **postgres** и **app** **running** / **healthy**.
2. **Postman — очистка:** `POST http://localhost:8083/dev/clear` → **204**.
3. **Postman — проверка пусто:** `GET http://localhost:8083/cars` и `GET http://localhost:8083/clients` → `[]` или пустые списки.
4. **Терминал — seed** (лучше **малое** `--count` для быстроты, например 5):  
   `.\.venv\Scripts\python.exe seed.py --count 5 --endpoint clients`
5. **Postman — снова список:** `GET http://localhost:8083/clients` — **пять** объектов, поля **не одинаковые** (Faker + уникальные `driverLicense` / телефоны по логике скрипта).
6. (Опционально) **k6** один короткий прогон, чтобы показать связь «**данные есть** → **есть что грузить**».

### 7.3. Postman: что именно нажимать (шпаргалка)

| # | Метод | URL | Body | Ожидаемый результат |
|---|--------|-----|------|---------------------|
| 1 | POST | `http://localhost:8083/dev/clear` | нет (None) | **204 No Content** |
| 2 | GET | `http://localhost:8083/cars` | — | **200**, JSON-массив |
| 3 | GET | `http://localhost:8083/clients` | — | **200** |
| 4 | GET | `http://localhost:8083/rents` | — | **200** |
| 5 | POST | `http://localhost:8083/clients` | **raw JSON**, пример: `{"fullName":"Тест","driverLicense":"DL-TEST-1","phone":"+79990000001"}` | **201** или **200** (как в вашем API) |
| 6 | POST | `http://localhost:8083/cars` | JSON с полями `vin`, `model`, `color`, `rentalCostPerDay` (**число**), `city`, `salonName` | **201/200** |
| 7 | POST | `http://localhost:8083/rents` | JSON с `carId`, `clientId`, датами, `totalCost` — id из шагов 5–6 или из GET | **201/200** при валидных ссылках |

**Импорт коллекции:** **Import** → файл `zil/documentation/postman_collection.json` — если в коллекции есть переменная **`baseUrl`**, задайте **`http://localhost:8083`**.

**Если спросят «почему не `curl` в PowerShell`»:** в PowerShell `curl` часто = **Invoke-WebRequest**; для примеров из Linux используйте **`curl.exe`** или **Postman**.

### 7.4. Вопросы, которые часто задают (короткие ответы)

- **Почему `delete` в порядке rents → cars → clients?** — Из-за **внешних ключей**: сначала убираем **ссылки** (аренды), потом **то**, на что ссылались.
- **Почему Faker, а не ручной список имён?** — **Масштаб** (500+ записей) и **разнообразие** полей **без** огромного файла.
- **Почему убрали V2?** — Чтобы **не** путать **деплой** (схема) и **подготовку к тесту** (Python); объём теста **контролирует** флаг `--count`.
- **Безопасен ли `/dev/clear`?** — Для **учебного** стенда да; **в бою** такие маршруты **не** публикуют **или** прячут за **профилем dev** и **авторизацией** (у нас по ТЗ **достаточно** честного комментария в коде).
