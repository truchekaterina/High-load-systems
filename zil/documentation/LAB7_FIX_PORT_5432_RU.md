# LAB7 — как перейти с «не того» порта (например 5433/5437) на внешний **5432** на DB-ноде

## Сначала разберись, что есть что (чтобы не путать 5433 и 5432)

| Где | Что за порт | Зачем |
|-----|-------------|--------|
| **`zil/docker-compose.yml` → сервис `postgres`** | `5433:5432` | Это **локальная** БД `car_rental` для разработки на машине с проектом. **К LAB7 на hl12 не относится.** Менять для «исправить hl12» **не нужно**. |
| **DB-нода hl12 → твой `docker-compose.yml` (katya)** | `XXXX:5432` слева | **Снаружи** с hl12 (и с hl07) ты подключаешься к порту **XXXX**. Справа всегда **5432** — это порт **внутри контейнера** PostgreSQL. |
| **pgAdmin в compose на hl12** | В настройках сервера: **Host `postgres`, Port `5432`** | Так и должно быть: pgAdmin и Postgres в **одной** docker-сети. **Не** подставляй сюда 5433/5437 с хоста. |

Итого: «надо было 5432» в ТЗ обычно значит **внешний порт к Postgres на DB-ноде = 5432** и **`DBPORT` в приложении = 5432`**. Это возможно **только если** на **hl12** никто другой не занял порт **5432** на интерфейсе, куда ты стучишься (часто `0.0.0.0:5432`).

---

## Когда НЕ надо ничего «чинить»

Если на hl12 порт **5432 занят** другим процессом, **оставляешь** проброс вида `5437:5432` или `5433:5432` и в приложении ставишь **`DBPORT` равным этому левому числу**. Это **не ошибка** архитектуры, это ограничение хоста. На защите формулировка: «внутри контейнера Postgres слушает 5432, снаружи проброшен другой порт».

Ниже — сценарий **перехода именно на внешний 5432**, как ты просишь.

---

## Шаг 0. Зафиксируй, какой порт сейчас на hl12

Зайди на **DB-ноду**:

```bash
ssh -p 2312 hl@hlssh.zil.digital
cd ~/katya
grep -A3 "ports:" docker-compose.yml | head -20
```

Запомни строку у `postgres`, например `- "5433:5432"` или `- "5437:5432"`. **Левое** число — это твой текущий «внешний» порт.

---

## Шаг 1. На hl12 проверь, свободен ли порт 5432 на хосте

На **hl12**:

```bash
sudo ss -tulpn | grep ':5432' || true
```

- Если **пусто** или видишь только docker-proxy к **твоему** контейнеру после перезапуска — хорошо.
- Если видишь **другой** postgres/listen на 5432 — сначала выясни, что это (курс/админ). **Нельзя** просто так повесить второй сервис на тот же порт.

При необходимости:

```bash
sudo lsof -iTCP:5432 -sTCP:LISTEN
```

---

## Шаг 2. На hl12 поменяй проброс в `docker-compose.yml` на 5432:5432

На **hl12**, в каталоге compose (например `~/katya`):

```bash
nano docker-compose.yml
```

У сервиса `postgres` сделай **ровно**:

```yaml
    ports:
      - "5432:5432"
```

Сохрани файл.

**Важно:** pgAdmin в этом же файле **не трогай** — у него по-прежнему `8081:80` (или как у тебя). Подключение pgAdmin к БД: host **`postgres`**, port **`5432`**.

Перезапуск:

```bash
cd ~/katya
docker compose down
docker compose up -d
docker compose ps
```

Проверка с **hl12**:

```bash
docker exec -it lab7-postgres psql -U hl7 -d hl7 -c "SHOW max_connections;"
```

Проверка, что **с хоста hl12** открывается 5432:

```bash
nc -vz 127.0.0.1 5432
```

---

## Шаг 3. На hl07 проверь доступ к hl12:5432

На **app-ноде**:

```bash
ssh -p 2307 hl@hlssh.zil.digital
nc -vz hl12.zil 5432
```

Должно быть `succeeded`.

---

## Шаг 4. В репозитории выровняй `DBPORT` под 5432

Нужно, чтобы **везде** для LAB7 было **`5432`**, а не `5433`/`5437`.

### 4.1 `zil/src/main/resources/application.properties`

Было (пример):

```properties
spring.datasource.url=jdbc:postgresql://${DBHOST:localhost}:${DBPORT:5437}/...
```

Должно стать:

```properties
spring.datasource.url=jdbc:postgresql://${DBHOST:localhost}:${DBPORT:5432}/${DBNAME:hl7}?currentSchema=${SCHEMANAME:hl7}
```

(Имя БД/схемы подставь из **актуальной** строки таблицы курса.)

### 4.2 `zil/docker-compose.yml` → сервис `app`

Было:

```yaml
DBPORT: "5437"
```

Должно стать:

```yaml
DBPORT: "5432"
```

**Не трогай** блок локального `postgres` с `5433:5432` — это отдельная история.

### 4.3 Документация

В своих `LAB7_*.md` замени все упоминания внешнего порта **5437/5433** на **5432** для сценария hl12, чтобы не путаться.

## Шаг 5. Задеплой на hl07

На **hl07**:

```bash
cd ~/work/Labs_hls
git pull
cd zil
docker compose up --build -d --force-recreate app
docker exec -it zil-app env | grep DBPORT
docker compose logs app --tail 80 | grep jdbc
```

В логах JDBC должен быть вида:

```text
jdbc:postgresql://hl12.zil:5432/hl7?currentSchema=hl7
```

## Шаг 6. Туннель для настольного клиента с ПК (если нужен)

Если хочешь DBeaver/pgAdmin Desktop на Windows к **внешнему** 5432 на hl12:

```powershell
ssh -p 2312 -L 5432:127.0.0.1:5432 hl@hlssh.zil.digital
```

Дальше в клиенте: `127.0.0.1`, порт `5432`, БД `hl7`, пользователь/пароль как в `.env`.

**Внимание:** если у тебя **на Windows уже занят** локальный 5432, выбери другой локальный порт, например:

```powershell
ssh -p 2312 -L 15432:127.0.0.1:5432 hl@hlssh.zil.digital
```

и в клиенте подключайся к `127.0.0.1:15432`.

Веб-pgAdmin по-прежнему удобнее так:

```powershell
ssh -p 2312 -L 8081:127.0.0.1:8081 hl@hlssh.zil.digital
```

и браузер `http://localhost:8081`.

## Если после смены порта «пропали данные»

Обычно данные в **volume** и не пропадают. Если вдруг поднялся **новый пустой** кластер:

- проверь `docker volume ls` и имена volume в compose;
- не делай `docker compose down -v` без необходимости.
